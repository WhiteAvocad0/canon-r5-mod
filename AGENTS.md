# Canon R5 Mod

Public source-preview project for original Canon EOS R5 firmware `2.2.1` only. Provides two separate offline-buildable profiles:

1. `shutter-feedback` (default): custom startup + shutter WAV speaker playback; immutable private reference is user-confirmed `build36` (`562,144` B, `3579cecf...`).
2. `xpan-crop` (experimental, silent by default): `2.71:1` (`512:189` ~ `2.709:1`) XPan crop mode (`8192x3024` Large JPEG, `8192x5464` CR3 crop `(0,1220,8192,3024)`, replaces `16:9`, Q `"XPan"` label, live LCD/EVF framing, playback masking). Prior private candidate `466ca8fe` (`c9f06053`) was user-confirmed on rear LCD landscape first-open playback (`DbgRA127`), live LCD/EVF, Q label, and saved crop output; earlier `128 GB` silent XPan (`1b7bfcfa`) + CFexpress coexistence was also confirmed; latest native reference `4838eb81` (`427bb28d`, `117` inputs, `31` hooks, `17` pages, `8` L2 tables, `120` witnesses, `948,152` free bytes, `184`B fit / `40`B view owner, `67` V1 reasons) extends playback masking to `(device in {0,1}, orientation in {0,2}, effective r7=0)` and was reported working in the owner's four-case normal ▶ session on 17 November 2026 (private research suite: `289` tests and independent reviews). The current public profile also carries the automatic post-shot review fix (immediate XPan bars, 16:9 outline hidden for XPan only; `34` hooks, `20` pages, `10` L2 tables, `137` witnesses), verified on private lab build `a7e92a3d` on 18 November 2026. The public repackaged image is hardware-untested.

Preserve native baseline C/ASM/linker behavior across both profiles and clearly distinguish source facts, host tests, private hardware baselines, and hardware-untested public repackaged builds.

- Use `rtk` when already available; otherwise run the documented commands directly. Do not install it merely to follow this guide.
- Distinguish source facts, host tests, and user-reported camera evidence. Neither public repackaged build (`shutter-feedback` or `xpan-crop`) has itself been hardware-tested. Private `build36` (`shutter-feedback`) was user-confirmed for XP startup, Mambo shutter, and normal shooting on `16 GB` SDHC/FAT32 and full-capacity `128 GB` SDXC/exFAT (SDXC returned files, repeated boots, and longer shooting unverified). Private `xpan-crop` (`466ca8fe`) was user-confirmed for rear LCD landscape first-open, live LCD/EVF, Q label, and `RAW+Large JPEG` XPan capture; `4838eb81` normal ▶ portrait LCD/EVF playback was reported working in the four-case session on 17 November 2026; private `a7e92a3d` (18 November 2026, `128 GB` card) was reported working for XPan-only immediate automatic-review bars with the outline hidden, stock Full-frame review, burst and EVF, and the REC-press `ding`. Public repackaging and other qualities/modes/active auto-rotation remain unverified/declined.
- Do not commit or upload Canon ROM/FIR/dumps, built images/objects/toolchains, real diagnostic dumps/photos (`.CR3`/`.JPG`), user audio (XP/Mambo), generated Canon ROM pages/tables/vectors, credentials, build outputs, private lab history, or local plans. Users supply their own ROM dump (and two WAV clips for `shutter-feedback`). Publication is source+docs only, no binary release.
- Preserve native baseline C/ASM/linker behavior. All addresses are original R5 `2.2.1`-specific. Other R5 firmware/R5 C/R5 Mark II/R6/R6 II/R6 III are unsupported and need independent ports; no cross-model binary testing.
- No camera-side BootDisk/bootflag activation, firmware/NVRAM writes, formatting, partitioning or MBR writes. Card instructions require backups and correct model/firmware. The CLI builder (`tools/build.py`) builds offline only and never writes cards.
- Card boot markers (owner decision, 18 November 2026, issue #16 Phase 2): the GUI build assistant alone offers opt-in boot-marker preparation (`tools/cardprep/`, the "Prepare card" tab). It is the only raw-device writer. Keep its safeguards: the person confirms the card was formatted in the camera (the tool never formats); only removable SD cards in an SD slot are offered (no internal, boot or system disks, disk images, USB readers or sizes outside 2 GB-2 TiB); the person confirms by typing the volume name; the MBR and the partition's first 24 sectors are backed up to a timestamped folder on the computer and verified by re-reading before any write; only the planned sectors are written (FAT32: `EOS_DEVELOP` at `0x47` and `BOOTDISK` at `0x5C` of the primary boot sector; exFAT: `BOOTDISK` `+122` and `EOS_DEVELOP` `+130` in both boot regions plus both checksum sectors per the Microsoft exFAT spec, backup region first), by the whitelisted helper (`helper.py`) that refuses unless the current bytes match the expected-before SHA-256; every byte is read back and compared, `diskutil verifyVolume` runs, and the volume is unmounted (never ejected) and remounted; restore uses the same checks; failures are reported, never silent. Raw access needs the OS password prompt (`osascript ... with administrator privileges`); never ask for, store or pass a password. Anything unexpected (unknown filesystem, geometry mismatch, MBR inconsistent with the volume, non-512-byte sectors, unexpected bytes where markers go) is refused. Only 512-byte-sector FAT32 and exFAT are handled. macOS real-device use is untested until the owner verifies it; Windows/Linux offer untested detection only and no writes.
- Firmware admission must accept per-camera settings differences outside immutable target code while retaining strict exact-code/patch/table/resource checks (`config/target_contract.json`, `config/xpan_target_contract.json`). Preserve actual caller ROM digest and paths as provenance, not a private camera full-dump hash as compatibility identity. Derive ROM-backed XPan inputs (`target-page.bin`, `frame_row_constants.h`, `menu-vector.bin`, `feature-targets.h`) into `--output` only after strict target admission. No `--force` or skip-target-check option.
- Audio roles (`shutter-feedback` default): startup WAV and shutter WAV separate, full clips, 48kHz mono 16-bit PCM, 32-byte zero alignment only, no normalization/trimming. Busy effects drop; no delayed replay. No immediate user mute or full burst/movie/latency/shutdown certification claimed.
- XPan role (`--profile xpan-crop`): silent by default (`R5_CROP_ONLY=1`), forbids `--startup-wav`/`--shutter-wav`, links zero PCM/puff symbols, disables added shutter playback (`play_shutter = 0`) while retaining the headless control/report worker. Do not remove that worker; it maintains MMU/report state. Canon's own Beep setting is unchanged.
- Automatic post-shot review fix (always on in `xpan-crop`, no option): three cooperating hooks. `review_crop` at `0xE063FBEE` changes an exact full-source review descriptor tuple `{0,0,0,0,1024,682}` to `{0,152,0,152,1024,378}` (3 words); `xpan_authority` at `0xE054C530` passively records each shot's Job (signature `0xE2083738`, JobID `[obj+0x3C0]`, aspect `[obj+0x14C0]`, flags `[obj+0x19F0]`); `xpan_review_gate` with the outline hook at `0xE0A956FE` lets both act only for a fresh single-claim authority with aspect `7` and `(flags & 0x101) != 0`. Full frame and bursts (`MULTIPLE`) keep the stock review. Decisions are kept as `.bss` counters only; no report rows. Capacity is `CODE_PATCH_MAX 35`, `MULTI_MAX_PAGES 21`, `MULTI_MAX_TABLES 10`.
- Movie record indicator (issue #14, `--profile xpan-crop --record-indicator {off,ding,chirp2,2k150loud}`, default `off`): opt-in only. `off` links no indicator code, hook, page or fingerprint check (`34/20/10/137`; with the indicator `35/21/10/139`). When selected it adds one observer hook (`GUI_SetRecordingState` `0xE07C6FBC`, counter only, REC press `0->1` from LR `0xE0B0B883`), a deterministic integer cue generated once into a 32-byte-aligned buffer by the worker (no WAV input, no user audio), a non-blocking `SE_BeepStart` step (SE id `2`, AudioCtrl mask `{1,4,5}`, bounded busy retry and observe timeout, no late replay) and a minimal `R5T1` counter report. Its hook page and two guard pages are admitted only through `record_indicator_code_fingerprints`. The `ding` cue was user-tested on a private lab build; the public repackaging is hardware-untested.
- Maintain GPL-2.0-or-later notices from Magic Lantern-derived boot/footer work; no Canon affiliation or endorsement. Do not attest human review or broader device support.
- Portable documented CLI:
  - Audio (default): `python3 tools/build.py --rom PATH --startup-wav PATH --shutter-wav PATH --toolchain DIR --output DIR`
  - Silent XPan: `python3 tools/build.py --profile xpan-crop --rom PATH --toolchain DIR --output DIR`
  - XPan + record indicator: add `--record-indicator ding`
  Outputs ignored under `build/` by convention. CLI never contacts camera/media.
- `config/features.json` (`tools/features.py`) is the single feature manifest: profiles, WAV input policies, options, profile dependencies and per-feature status. `tools/build.py` derives its selection CLI and rules from it, and the prototype build assistant (`tools/gui/`, standard-library Tkinter, issue #16 Phase 1) derives its checklist from it. The assistant builds through the CLI and copies only to an already-prepared card's folder (backup, temp-then-rename, SHA-256 readback); the copy step never formats, writes boot sectors or deletes anything but its own temp file. Boot sectors are written only by the separate "Prepare card" step described above.
- Host tests must run without private lab paths/assets or ARM toolchain. Real-ROM cross-build verification is separately opt-in and reported distinctly. Do not install unrelated software or dependencies automatically.
