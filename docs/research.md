# Feature research

These are feasibility questions and experimental tracks for the original Canon EOS R5 on firmware `2.2.1`. Except for the `shutter-feedback` baseline, the experimental `--profile xpan-crop` developer preview and its opt-in `--record-indicator` / `--record-stop-indicator`, these ideas are **not implemented camera features**. Each issue records stock functionality, the intended extension, implementation dependencies, and verification needed.

| Proposal | Current evidence / status |
| --- | --- |
| [Custom `2.71:1` XPan crop/menu mode?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/3) | Experimental silent `--profile xpan-crop` source preview (see [docs/xpan.md](xpan.md)). Private reference `4838eb81` normal ▶ LCD/EVF landscape/portrait session reported working on 17 November 2026, supported by returned playback diagnostics. The automatic post-shot review fix (immediate XPan bars, outline hidden for XPan only, stock review for Full frame and bursts) is now part of the profile; it was verified on private lab build `a7e92a3d` on 18 November 2026. The public `xpan-crop` + `ding` build passed a short owner check on 18 November 2026 (boot, live framing, immediate review, REC `ding`). |
| [JSON colour recipes and SD Picture Style bank?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/9) | A private host worksheet prototype passes five tests. Native JSON/PF3 loading, property schemas, and rendering refresh remain unverified. Canon already supports PF2/PF3 in three User Def. slots. **Not implemented.** |
| [Independently calibrated HNCS-inspired profiles?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/4) | Needs controlled R5/reference captures and measurable rendering goals. No authentic HNCS import format or equivalent calibration is established. **Not implemented.** |
| [Selectable sound packs, volume and quick mute?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/7) | Builds on working speaker playback; runtime file loading, control mapping, and safe active-playback cancellation need separate proof. **Not implemented.** |
| [Still-photo zebras, false colour and waveform?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/6) | Canon already has movie zebras. Investigate still-mode availability, input ranges, and display-layer ownership. **Not implemented.** |
| [Anamorphic desqueeze preview?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/5) | Requires a verified preview scaler/compositor path and correct AF/touch coordinates. Initial scope would leave recorded files unchanged. **Not implemented.** |
| [Programmable exposure sequences and interval ramping?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/10) | Extends existing AEB, bracketing, and timers; needs verified actuation, completion, and settings-restoration contracts. **Not implemented.** |
| [Named preset libraries and session reports?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/8) | Canon already provides C1–C3 and ten card settings files. Investigate organization/differences and preserve unknown binary fields. **Not implemented.** |
| [M-Film film simulation integration roadmap?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/11) | Film-simulation research: R5 capture/colour-pipeline adaptation, data formats and licensing need verification. **Not implemented.** |
| [29:59 continuous movie recording limit research?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/12) | A private lab build replaced the limit getter `0xE07700C6` (`1799000`/`449000` ms). Returning 60 s made a normal take auto-stop at 1:00 through `EndMovieRecSequence`, so the getter controls the auto-stop. A 59:59 build is pending a long-take test. **Not in the public profile.** |
| [Apple-style Live Photos / iPhone playback?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/13) | A private host-side packager (an R5 still plus a short clip become a paired Live Photo) passed Mac checks with real R5 media. The iPhone check is pending. **Not in this repository.** Automatic pre/post-shutter motion still needs verified encoder/buffer ownership and capture transitions. |
| [Movie Record button audible start/stop beep?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/14) | **Start and stop cues implemented as the opt-in `xpan-crop` options `--record-indicator` and `--record-stop-indicator` (both default off; see [docs/usage.md](usage.md#movie-record-indicator---record-indicator)).** A `ding` on the REC press was user-tested on a private lab build on 18 November 2026 (worked correctly; in earlier private runs the record-state hook saw 6/6 confirmed starts and 5/5, then 7/7 cues settled without errors, AF beep unaffected). The cue is quiet in the clip (about −32 dBFS). The public `ding` image `0adff001` played the cue in the 18 November 2026 owner check. The `dong` stop cue plays once per take when RecState returns to idle after a confirmed start; with the `ding` the owner tested private lab build `fbf31293` on 18 November 2026 and reported "confirmed that the dong works perfectly good" (lab test plan: three takes, a quick take, clip playback, AF beep; per-item results not recorded). The public `ding` + `dong` image `01956513` (built from `f4b2848`) passed a short owner check on 18 November 2026 (boot, live XPan framing, immediate review bars, a Full-frame control, the ding and dong over several takes, no dong in the played clip, the AF beep); `ding`-only and `dong`-only images from this version are new images and hardware-untested. |
| [Screenshots and screen recording?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/15) | **One-press screenshot implemented as the opt-in `xpan-crop` option `--screenshot rate` (see [docs/screenshot.md](screenshot.md)): RATE in ▶ saves an all-layers 2400×1600 JPEG through Canon's own encoder; private lab build-22 was reported working on 22 November 2026, public image `809d3767` passed a short owner check the same day (3:2 photos; XPan photos were cancelled). Screenshot anywhere (RATE in live view or a menu, JPEG at the next INFO in ▶; XPan photos through the last good photo) was owner-reported working on a private lab build on 22 November 2026, and its automatic INFO on ▶ entry ran on private lab builds on 23 November 2026; screenshot code identical to the public RC image `e2e7048d` checked on camera on 23 Nov 2026; this exact image was not separately camera-run.** Earlier research: The stock `SaveVRAM` event procedure (`0xE023652E`), run from a Canon Basic script in playback, captured the GUI/OSD layer on a private lab card. It doesn't capture the photo or live-view plane; a host can composite the overlay over the photo file. Full-frame-rate recording isn't feasible on camera (2–9 MB per frame). Canon's HDMI output, which sends menus and playback to an external device, is the practical recording route. **Not implemented.** |

ROM strings are leads, not callable function addresses; every binding must be verified in disassembly/ROM and [Canon's R5 manual](https://cam.start.canon/en/C003/manual/html/index.html).

Colour work starts with documented [EOS Utility PF2/PF3 registration](https://cam.start.canon/en/S003/manual/html/UG-02_CameraSetting_0020.html) and [Picture Style Editor](https://cam.start.canon/en/S004/manual/html/UG-03_ImageChara_0020.html). JSON describes a recipe; it does not establish an image-processing capability. [Hasselblad's HNCS description](https://www.hasselblad.com/learn/hasselblad-natural-colour-solution/) covers a calibrated capture-through-post system, so a look with similar intent must be measured independently and clearly labelled.

Experimental research prototypes remain offline until their interfaces and behavior are verified. No additional camera model, firmware, colour-processing, Live Photo, or movie-limit support is implied by these proposals.
