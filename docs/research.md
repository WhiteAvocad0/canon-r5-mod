# Feature research

These are feasibility questions and experimental tracks for the original Canon EOS R5 on firmware `2.2.1`. Except for the `shutter-feedback` baseline and the experimental `--profile xpan-crop` developer preview, these ideas are **not implemented camera features**. Each issue records stock functionality, the intended extension, implementation dependencies, and verification needed.

| Proposal | Current evidence / status |
| --- | --- |
| [Custom `2.71:1` XPan crop/menu mode?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/3) | **Published as experimental silent `--profile xpan-crop` source preview** (see [docs/xpan.md](xpan.md)). Private prior candidate `466ca8fe` confirmed immediate rear LCD landscape first-open bars (`DbgRA127`), live LCD/EVF framing, Q `"XPan"` label, and `8192x3024` Large JPEG / `8192x5464` CR3 crop `(0,1220,8192,3024)` output. Latest `4838eb81` portrait LCD / EVF playback extension is software-verified only; public repackaging is hardware-untested. |
| [JSON colour recipes and SD Picture Style bank?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/9) | A private host worksheet prototype passes five tests. Native JSON/PF3 loading, property schemas, and rendering refresh remain unverified. Canon already supports PF2/PF3 in three User Def. slots. **Not implemented.** |
| [Independently calibrated HNCS-inspired profiles?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/4) | Needs controlled R5/reference captures and measurable rendering goals. No authentic HNCS import format or equivalent calibration is established. **Not implemented.** |
| [Selectable sound packs, volume and quick mute?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/7) | Builds on working speaker playback; runtime file loading, control mapping, and safe active-playback cancellation need separate proof. **Not implemented.** |
| [Still-photo zebras, false colour and waveform?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/6) | Canon already has movie zebras. Investigate still-mode availability, input ranges, and display-layer ownership. **Not implemented.** |
| [Anamorphic desqueeze preview?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/5) | Requires a verified preview scaler/compositor path and correct AF/touch coordinates. Initial scope would leave recorded files unchanged. **Not implemented.** |
| [Programmable exposure sequences and interval ramping?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/10) | Extends existing AEB, bracketing, and timers; needs verified actuation, completion, and settings-restoration contracts. **Not implemented.** |
| [Named preset libraries and session reports?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/8) | Canon already provides C1–C3 and ten card settings files. Investigate organization/differences and preserve unknown binary fields. **Not implemented.** |
| [M-Film film simulation integration roadmap?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/11) | Film-simulation research: R5 capture/colour-pipeline adaptation, data formats and licensing need verification. **Not implemented.** |
| [29:59 continuous movie recording limit research?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/12) | Read-only ROM inspection identified candidate limit/timer getters (`0xE07700C6`, `1799000`/`449000`) and warning state (`0xE07AF3F4`), while the actual in-progress stop owner remains unproven. **Not implemented.** |
| [Apple-style Live Photos / iPhone playback?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/13) | Offline feasibility research complete; **not implemented or iPhone-tested**. First validate local still/video pairing and PhotoKit import. Automatic pre/post-shutter motion needs verified encoder/buffer ownership and capture transitions; the current resident allocation is not the camera's entire memory budget. |
| [Movie Record button audible start/stop beep?](https://github.com/WhiteAvocad0/canon-r5-mod/issues/14) | Offline source research complete; **not implemented or camera-tested**. Candidate recording-state accessors were identified, but the existing sound path has movie-mode audio gates. Passive state/routing observation and recorded-track microphone-pickup checks are needed before a cue prototype. |

ROM strings are leads, not callable function addresses; every binding must be verified in disassembly/ROM and [Canon's R5 manual](https://cam.start.canon/en/C003/manual/html/index.html).

Colour work starts with documented [EOS Utility PF2/PF3 registration](https://cam.start.canon/en/S003/manual/html/UG-02_CameraSetting_0020.html) and [Picture Style Editor](https://cam.start.canon/en/S004/manual/html/UG-03_ImageChara_0020.html). JSON describes a recipe; it does not establish an image-processing capability. [Hasselblad's HNCS description](https://www.hasselblad.com/learn/hasselblad-natural-colour-solution/) covers a calibrated capture-through-post system, so a look with similar intent must be measured independently and clearly labelled.

Experimental research prototypes remain offline until their interfaces and behavior are verified. No additional camera model, firmware, colour-processing, Live Photo, or movie-limit/beep support is implied by these proposals.
